## 0. Геометрия (не меняется)

## 3. Композиция по типам страниц

**Обложка (стр. 1).** Утверждена. Файл `design/cover-v1/artwork/cover-art.png`, `object-fit:cover`. **Не изменять** ничем.

**Выходные данные (стр. 2).** Центрированная статусная колонка: рубрика → «Письма памяти» → «Том I» → золотая линия → эмблема инициатора (h≈24 мм) + «Издана по инициативе АНО…» → блок «При поддержке» + партнёрская эмблема (h≈19 мм) → «Москва · 2025» над тонкой линией. Без декоративных фрагментов писем. Новые тексты/логотипы не добавлять.

**Портрет председателя + приветствие (стр. 3–4).** Левая: плашка «портрет (118×150 мм, белая рамка) + имя + золотая линия + должность» — портрет поддерживает текст. Правая: эмблема → рубрика → «Приветственное слово» → роль → лид → 2 сбалансированные колонки с буквицей → валедикция. Весь оригинальный текст, портрет, подпись, должность и порядок сохраняются.

**Содержание (стр. 5–8).** Типографика из `content/manifests/reference-family-order-reset.json`, канонический порядок 74 семей, 2 разворота. Строка: № (золото) · имя (navy) · регион (secondary) · точечный лидер · динамический номер `—`. Нумерация — динамическая до финальной вёрстки. Разрешено увеличивать число страниц ради читаемости; плотность держать комфортной.

**Ознакомительный разворот героя (стр. 9).** Утверждённый приём: крупная флагманская вырезка (по пояс, prawy-нижний якорь), meta слева сверху (регион/город · имя · автор письма), медаль + герб + подпись-роль, фоновая карта с феатером, бордовая карточка-цитата из письма слева снизу. Композицию с нуля не переделывать.

**Разворот письма (стр. 10).** Левый столбец — семейные фото (групповое сверху, портрет ребёнка снизу, подписи «Семейный архив»/имя). Ниже-справа — детский рисунок. Основной блок — светлая карточка «Расшифровка письма», прижатая к содержимому. Под всем — подлинная рукопись как документальный фон.

## 4. Правила карты
- Только версия с **запечённой альфа-маской** (`assets/maps/<region>-feathered.png`). Генерация — `scripts`-независимый PIL-скрипт (edge-vignette + Gaussian feather + мягкое ослабление светлого фона).
- Края растворяются **неравномерно**; карта не должна читаться как прямоугольная серая карточка.
- Границы субъектов различимы; нужный регион выделен точно (бордовый).
- Проверять результат **в экспортированном PDF/растре**, не только в браузере. На CSS-only эффекты (mix-blend без альфа) не полагаться.
- Отображение: `opacity ≈ .58–.62`, `object-fit:contain`.

## 5. Правила флагманского портрета
- Один крупный герой на разворот, масштаб/роль — как у Анастасии (V12-ориентир), кадр примерно по пояс.
- Только проверенная прозрачная вырезка из `assets/processed-flagships/<hero>/…` (белый прямоугольный фон недопустим).
- Волосы и края не повреждены; безопасное расстояние от сгиба и края; текст не заходит на лицо.

## 6. Правила подлинной рукописи
- Физический оригинал **обязательно присутствует** как фоновый документальный слой (`letter-page::before`).
- `opacity ≈ .16`, `grayscale(.4) contrast(.9)`, `mix-blend-mode:multiply`, лёгкий поворот. Заметен как первоисточник, но не конфликтует с расшифровкой.
- Без желтизны, «прокуренной бумаги», архивных штампов и скрапбук-декора. Лист = современная бережная издательская реконструкция.

## 7. Правила чистой расшифровки
- Публичный текст — санкционированный reader-вариант; утраченные фрагменты — нейтральное `…`; слова не додумываются, смысл не восстанавливается догадкой.
- Служебные пометки (`[край обрезан]`, `[подпись — нрзб]` и пр.) **запрещены** в публичном слое; хранятся в скрытом редакционном слое (`div.editorial-hidden`), в манифесте расшифровки и в changelog.
- Заголовок: «Расшифровка письма». Исходная дипломатическая расшифровка не удаляется и не перезаписывается.

## 8. Правила официальных и вводных страниц
- Ничего из референса не теряется: тексты, портрет, подпись, должность, все позиции содержания, медаль, герб, карта, все фото семьи, рисунок, рукопись, полная расшифровка. Текст письма не сокращается и не переписывается.
- Каждый элемент имеет явное размещение; ничего не исчезает молча.

## 9. Что нельзя менять при автоматизации
1. Обложку (дизайн, композицию, цвет, файл).
2. Геометрию листа/страницы/полей/сгиба (раздел 0).
3. Цветовые токены и шрифтовую систему (разделы 1–2).
4. Требование запечённой альфа-маски карты (раздел 4).
5. Двухслойную модель расшифровки и запрет служебных пометок в публичном тексте (раздел 7).
6. Порядок и принадлежность материалов по референсу; состав контента.
7. Разделение флагманских и архивных процессов; вырезка фона — только у подтверждённого флагмана.
8. Нельзя вводить альтернативные шаблоны/направления — только этот эталон.

## Вердикт

```
NOT_READY_TO_LOCK
```

**Пояснение:** визуальный шаблон дизайн-готов — все дефекты V12 устранены и проверены в масштабе печати. Оставшиеся блокеры — **не дизайнерские**, а контентные согласования, которые по правилам reset может снять только владелец (`REVIEW_REQUIRED` нельзя закрывать догадкой). Редизайн не требуется.

**Конкретные блокирующие пункты (только они):**
1. **Расшифровка `hero-001`:** `reader_version_approved: false`, `status: REVIEW_REQUIRED` — публичный текст письма не сверен вторым человеком и не утверждён владельцем. До утверждения замораживать содержимое разворота письма нельзя.
2. **Ремап страниц архивных материалов:** фото `photo_02/03` и рисунок `hero-001` имеют `source_page_status: REVIEW_REQUIRED_REMAP_TO_FINAL_REFERENCE`; рисунок — `print_qa_status: REVIEW_REQUIRED`. Требуется подтверждение соответствия финальному референсу.
3. **Provenance флагман-вырезки:** используемый PNG байт-в-байт совпадает с файлом из `assets/background-removed/needs-fix/`. Нужно официально перевести подтверждённый файл в `processed-flagships` со статусом «проверен», а не «needs-fix».
4. **Артефакты региона в манифесте:** `«. Санкт-Петербург»`, `«Карачаево - Черкесская»` — подтвердить каноническое написание в `reference-family-order-reset.json` (в шаблоне применена только нейтральная нормализация отображения).
5. **Реальная пагинация содержания:** сейчас динамическая (`—`). Перевести в реальные номера можно только после сборки семейных блоков.

После письменного снятия пунктов 1–5 владельцем шаблон переводится в `READY_TO_LOCK` **без изменения дизайна**.
