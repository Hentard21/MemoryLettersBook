# Print Spec Lock

Статус: техническая спецификация интерьера после утверждения `PRINT_V20_CLIENT_TEMPLATE_APPROVAL.pdf` как **Design Lock**.

Этот документ фиксирует геометрию и печатные ограничения. Он не разрешает менять обложку, визуальную концепцию, типографику или композиционные шаблоны V20. Технические исправления допустимы только для выполнения требований печати и должны сохранять внешний вид.

## 1. Формат интерьера

| Параметр | Зафиксированное значение |
|---|---:|
| Trim одной страницы | 260 × 200 мм |
| Bleed | 3 мм со всех четырёх сторон |
| MediaBox / BleedBox одной страницы | 266 × 206 мм |
| Просмотровый разворот | 526 × 206 мм |
| Линия сгиба просмотрового разворота | x = 263 мм |
| Допуск округления PDF-координат | ±0,05 мм |

Обложка не входит в интерьер. Она экспортируется отдельным wrap-файлом только после расчёта толщины корешка.

### Обязательные page boxes отдельной страницы

Координаты ниже указаны в миллиметрах от нижнего левого угла страницы:

- `MediaBox = [0, 0, 266, 206]`;
- `BleedBox = [0, 0, 266, 206]`;
- `TrimBox = [3, 3, 263, 203]`;
- `CropBox` для производственного файла совпадает с `MediaBox`, если типография не требует иного;
- `ArtBox` не обязателен и не подменяет `TrimBox`.

Цвет и фактура, доходящие до линии реза, должны продолжаться до `BleedBox`. Текст, лица, гербы и награды не могут использовать bleed как рабочую область.

## 2. Получение отдельных страниц из просмотрового разворота

Разворот 526 × 206 мм нельзя делить простым разрезом на x = 263 мм: тогда исчезнет внутренний bleed. Для технического экспорта используются перекрывающиеся области шириной 266 мм:

- левая страница: область разворота `x = 0…266 мм`; её trim в координатах разворота — `x = 3…263 мм`;
- правая страница: область разворота `x = 260…526 мм`; её trim в координатах разворота — `x = 263…523 мм`.

Таким образом, вокруг сгиба сохраняется по 3 мм внутреннего bleed с обеих сторон. Этот способ допустим только для фона и элементов, которым разрешено доходить до реза. Дублирование текста или важных деталей в перекрывающихся 6 мм запрещено.

## 3. Поля и safe zone

Для основного живого содержания фиксируются:

| Поле | Значение от TrimBox |
|---|---:|
| Внутреннее, у сгиба | 22 мм |
| Внешнее | 17 мм |
| Верхнее | 15 мм |
| Нижнее | 16 мм |

Локальные live-area координаты в просмотровой системе с началом в левом верхнем углу `MediaBox`:

- левая страница: `x = 20…241 мм`, `y = 18…187 мм`;
- правая страница: `x = 25…246 мм`, `y = 18…187 мм`.

Утверждённые страницы полного приветственного слова или длинного манифеста могут использовать верхнее и нижнее поле 10 мм, если автоматический overflow-check пройден. Фолио и короткий running footer могут стоять в 9–10 мм от нижней границы trim, как в Design Lock, но не могут входить в bleed. Это вертикальные исключения; исключения по внутреннему полю для текста, лиц, гербов и наград не допускаются.

На просмотровом развороте внутренняя опасная полоса равна `x = 241…285 мм`. Фон, прозрачные края вырезанной фигуры и незначимые детали одежды могут заходить в неё. Не должны заходить:

- основной текст, цитаты и номера содержания;
- лица и волосы у контура лица;
- гербы, награды и подписи к ним;
- QR-коды и мелкие документальные детали, если они появятся позже.

## 4. Паритет и начала разделов

- чётные страницы всегда стоят слева (`verso`);
- нечётные страницы всегда стоят справа (`recto`);
- первая страница интерьера — правая, нечётная;
- выходные данные и партнёры занимают первую правую страницу интерьера;
- каждый двухстраничный вводный или семейный блок начинается с чётной левой страницы;
- разворот-продолжение идёт непосредственно после основного разворота той же семьи;
- если следующий раздел попадает на правую страницу, генератор вставляет технически пустую страницу до него и пересчитывает содержание;
- содержание строится только после стабилизации пагинации.

Текущие напечатанные фолио в V20 имеют обратный паритет, потому что левая половина первого просмотрового разворота ошибочно учитывает обложку как внутреннюю страницу. В производственном плане обложка исключается, а номера интерьера пересчитываются: правая половина первого разворота становится страницей 1; со второго разворота левая половина получает чётный номер, правая — следующий нечётный.

## 5. Изображения

Effective DPI считается по фактическому размеру размещения, а не по метаданным исходного файла.

- `>= 250 ppi`: допускается к печатному пилоту;
- `180…249,9 ppi`: обязательная очередь `replace / upscale / reduce placement`; экспорт возможен только с явным решением в preflight manifest;
- `< 180 ppi`: блокирующая ошибка для значимого изображения;
- низкоконтрастный декоративный фон ниже 180 ppi может получить только явный waiver с ролью `decorative_background`; waiver не распространяется на портрет, рукопись, рисунок, герб или награду.

Автоматически изменять исходные изображения, запускать апскейл или уменьшать утверждённую композицию preflight-скрипту запрещено.

## 6. Цвет и прозрачность

- рабочие proof-файлы могут оставаться RGB/sRGB;
- CMYK-профиль и Output Intent выбираются только после получения требований типографии;
- прозрачность и soft masks сохраняются: PDF/X-4 поддерживает живую прозрачность;
- финальный производственный PDF не должен содержать неуправляемый DeviceRGB без согласованного Output Intent;
- принудительная конверсия в случайный CMYK-профиль запрещена.

## 7. Шрифты

- все используемые шрифты и подмножества должны быть физически включены в PDF;
- для production-файла предпочтительны `Type0/CIDFontType2` с внедрённым TTF/OTF;
- наличие `Type3` является preflight warning и требует либо повторного экспорта статическими шрифтами, либо письменного допуска типографии;
- случайный fallback-шрифт считается ошибкой даже для одного знака;
- перевод всего текста в кривые не является базовым решением: он ухудшает проверяемость и поиск текста.

## 8. PDF/X-4 gate

Файл можно объявлять PDF/X-4 только при одновременном выполнении условий:

1. отдельные страницы с корректными `MediaBox`, `BleedBox` и `TrimBox`;
2. PDF 1.6 или новее, корректная XMP-идентификация PDF/X-4;
3. согласованный типографией CMYK Output Intent;
4. управляемые RGB/CMYK-объекты;
5. все шрифты внедрены, Type3 либо устранены, либо приняты типографией;
6. нет шифрования;
7. прозрачность и soft masks сохранены без визуальной поломки;
8. после конвертации повторно пройдены DPI, box, font и visual preflight.

Chromium/pypdf-сборка сама по себе не является PDF/X-4-конвертером. Финальная конвертация выполняется отдельным проверенным инструментом с профилем конкретной типографии.

## 9. Воспроизводимая проверка

```powershell
python scripts\audit_pdf_preflight.py `
  design\prototypes\print-v20\PRINT_V20_CLIENT_TEMPLATE_APPROVAL.pdf `
  --json workspace\reports\v20-print-preflight-data.json
```

Скрипт работает только на чтение и не модифицирует проверяемый PDF.

Для V21 generator pilot блокирующая проверка и воспроизводимая сборка запускаются так:

```powershell
python scripts\generate_v21_pilot.py --render
python scripts\validate_v21_pilot.py `
  --output-dir design\prototypes\print-v21 `
  --pdf design\prototypes\print-v21\PRINT_V21_GENERATOR_PILOT.pdf `
  --minimum-dpi 180 `
  --strict
```

V21 gate дополнительно сверяет реальный `map_feature_id`, конкретные файлы герба и награды из канонических реестров, загрузку изображений, DOM-переполнение расшифровок и содержания, `object-fit: contain` у флагманов и координаты текста относительно внутренней safe zone 22 мм.
