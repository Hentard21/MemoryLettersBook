# Ручная обработка Gigapixel после reset

Рабочая папка: `assets/for-gigapixel/`.

Партия от 19.07.2026 завершена: 281 результат принят в `assets/production-ready/`, а 281 входной файл сохранён в архиве. Активная папка снова является пустым staging и не должна автоматически заполняться повторно.

```text
flagship/<hero_id>/  подтверждённые главные изображения
archive/<hero_id>/   семейные и поддерживающие фотографии
drawings/<hero_id>/  исходные детские рисунки, которым нужен апскейл
```

## Порядок обработки

1. Обрабатывать героев строго по `reference_order` из `assets/families/family-processing-plan.json`.
2. Сначала `flagship/`, затем архив и рисунки этой же семьи.
3. Не переименовывать исходный stem; к результату добавлять `_upscaled`.
4. Не перезаписывать входной файл.
5. Не менять лица, одежду, предметы, фон и взаимное расположение людей.
6. Для рисунков сохранять детский штрих и исходное содержание.
7. Результат проверять при масштабе 100% до включения в семейный manifest.

CutItOut запускается только после Gigapixel и только для флагманов, у которых в плане стоит `needs_cutout: true`.

Папка создаётся повторяемой командой:

```powershell
python scripts\export_for_gigapixel.py --dry-run
python scripts\export_for_gigapixel.py --apply
```

Экспорт не включает уже улучшенные производные и не добавляет рукописи.

После ручной обработки новая партия принимается только через безопасную проверку:

```powershell
python scripts\ingest_gigapixel_results.py --dry-run
python scripts\ingest_gigapixel_results.py --apply
```
