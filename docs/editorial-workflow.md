# Редакционный рабочий процесс

Как тексты проходят путь от исходника до сайта и печатной книги. Категории правок — в `AI_HANDOFF.md` (Editorial policy), поля сущностей — в `content-model.md`, журнал — `content/manifests/editorial-changelog.json` (+ CSV-зеркало).

## Принцип

Исходный текст — неприкосновенный слой. Все улучшения живут в отдельных полях (`normalized_text`, `edited_text`, расшифровки писем) и в журнале правок. В любой момент можно ответить на вопрос: «что здесь было в исходнике и кто, когда и почему это изменил».

## Семь шагов

### 1. Извлечение без изменений
Текст извлекается из исходника дословно → `source_text` (сейчас: `workspace/extracted-text/`, `source_quality: "pdf_reference"`). Этот слой не редактируется никогда, в том числе опечатки.

### 2. Техническая нормализация (SAFE_TECHNICAL_EDIT)
Автоматически: двойные пробелы, технические переносы PDF, восстановление абзацев, пробелы у знаков препинания, кавычки-«ёлочки» и тире, неразрывные пробелы, регистр заголовков по дизайну. Результат → `normalized_text`, `edit_status: technical_edit_applied`. Смысл, порядок слов и орфография автора не затрагиваются.

### 3. Предложения по литературной редактуре
Агент готовит предложения (категории APPROVAL_REQUIRED / FACT_LOCKED / UNCERTAIN_SOURCE): запись в changelog со статусом `proposal_created`, с объяснением и, где требуется, подтверждающим источником. Сами тексты сущностей при этом ещё не меняются.

### 4. Понятное сравнение «было / стало»
Каждое предложение выводится владельцу в виде наглядного диффа:

```
[ed-0042] hero-013, стр. 51 — категория: UNCERTAIN_SOURCE
БЫЛО:  …ОЛЕГ, РАДА, РАДОМИР г. Санкт- Петербур г. Санкт-Петербург
СТАЛО: …ОЛЕГ, РАДА, РАДОМИР г. Санкт-Петербург
Причина: в текстовом слое два текстбокса — усечённый и полный; канонический вариант виден в PPTX.
Источник: PPTX, слайд 51 (после получения).
```

Пакеты предложений удобно сводить в CSV (`editorial-changelog.csv`) или таблицу для построчного просмотра.

### 5. Решение владельца проекта
По каждой правке отдельно: `approved` / `rejected` / `deferred` (+ комментарий). Решение фиксируется в `owner_decision` записи журнала. Молчание ≠ согласие: без решения правка не применяется.

### 6. Публикуется только утверждённое
В сайт и печатную книгу попадает `edited_text` только при `edit_status: approved`; иначе используется `normalized_text` (а для писем — правило из `content-model.md`: `reader_friendly_transcription` только при `reader_version_approved: true`, иначе `diplomatic_transcription`).

### 7. Связь с исходником не теряется
У каждой сущности всегда сохраняются `source_text`, `source_ref` (страница PDF/слайд PPTX) и цепочка записей в changelog. Любую правку можно откатить до исходника одним действием.

## Статусы (сквозные)

```
not_reviewed → technical_edit_applied → proposal_created → approval_required → approved | rejected
                                                        ↘ source_verification_required (для FACT_LOCKED/UNCERTAIN_SOURCE)
```
