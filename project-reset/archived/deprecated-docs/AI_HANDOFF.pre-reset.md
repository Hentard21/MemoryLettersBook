## Editorial policy

Проект готовит **профессионально отредактированные версии** текстов для сайта и печатной книги. Исходные данные при этом не изменяются никогда: `source_text` сохраняется отдельно от любых правок, связь с исходником не теряется. Каждое изменение относится к одной из четырёх категорий и фиксируется в журнале `content/manifests/editorial-changelog.json` (процесс — в `docs/editorial-workflow.md`).

### SAFE_TECHNICAL_EDIT — допускается автоматически

- удаление двойных пробелов;
- исправление технических переносов из PDF (разорванные слова/строки);
- восстановление абзацев;
- нормализация пробелов вокруг знаков препинания;
- замена технически некорректных кавычек и тире («ёлочки», длинное тире);
- применение неразрывных пробелов (инициалы, «г.», числа с единицами);
- дизайнерское изменение регистра заголовков (КАПС ↔ обычный).

Результат кладётся в `normalized_text`; исходный текст всегда сохраняется отдельно в `source_text`.

### APPROVAL_REQUIRED — только с явного утверждения владельца проекта

- литературная редактура;
- сокращение;
- изменение порядка предложений или абзацев;
- удаление смысловых повторов;
- изменение заголовков;
- исправление авторской орфографии и пунктуации писем;
- создание адаптированной версии текста для сайта;
- изменение тона или стилистики.

Агент может **предлагать** такие правки (статус `proposal_created`, сравнение «было/стало»), но применять — только после решения владельца.

### FACT_LOCKED — нельзя менять без подтверждающего источника

Имена, фамилии, отчества, даты, звания, награды, города, регионы, родственные связи, авторство материалов, подписи к фотографиям, цитаты, факты биографии. Любое изменение — только со ссылкой на подтверждающий источник (`source_reference`: PPTX, документ, подтверждение семьи/редакции) и с утверждением владельца.

### UNCERTAIN_SOURCE — если исходник неоднозначен

- не исправлять догадкой;
- сохранять оригинальную запись дословно;
- добавлять предполагаемый вариант отдельным полем (не вместо оригинала);
- указывать уверенность (`confidence`);
- перечислять основания предположения;
- ставить статус `REVIEW_REQUIRED`.

Текущий список таких мест: `content/manifests/editorial-issues.pdf-stage.json`.

## Как устроен pipeline

```
source/reference.pdf  (не трогаем)
   │  scripts/01_analyze_pdf.py
   ▼
workspace/extracted-text/ + workspace/reports/pdf-analysis.json   ← сырые данные
   │  scripts/02_build_manifest.py
   ▼
content/manifests/ + content/entities/ + content/sections/        ← структурированный контент
   │  (будущие этапы)
   ├─► визуальная классификация сканов → уточнение манифеста
   ├─► приём PPTX → замена ассетов, source_quality: pptx_original
   ├─► сборка веб-страниц (JSON/Markdown + webp/avif)
   ├─► редакционный процесс (docs/editorial-workflow.md) → утверждённые тексты
   └─► сборка печатных разворотов (горизонтальный формат) → InDesign/IDML
```

Правило конвейера: **данные текут только слева направо**. `content/` перегенерируется скриптами, но ручные пометки (поля `manual_*`, `review_*`) при перегенерации сохраняются — см. `pptx-ingestion-plan.md`, раздел «Слои данных».

## Эталон данных

`source/reference.pdf` — **окончательный и единственный** эталон (PPTX утерян, см. баннер). Эталоном являются:
- тексты из `workspace/extracted-text/` (дословные, `source_quality: "pdf_reference"`);
- постраничная структура из `book-manifest.pdf-stage.json`;
- нативные мастера изображений `content/prototypes/*/assets/native/` — потолок качества картинок.

`source_quality: "pdf_reference"` — постоянная пометка исходника (не «временная до PPTX»). Улучшенные изображения (upscale) — производные: помечаются `derived`, рядом всегда лежит нативный оригинал. Спорные факты (имена/регионы/подписи) закрываются решением владельца или сверкой с семьями, а не PPTX.

Graphify настроен project-scoped в `.codex/skills/graphify/`. Локальная сборка без LLM выполняется `scripts/build_graphify_project_graph.py`; тяжёлые папки исключены через `.graphifyignore`.

Ни Graphify, ни Playwright, ни PDF skill, ни MarkItDown не являются источником фактов о героях. Любое имя, родство, регион, город, награда, цитата, принадлежность письма/фото/рисунка и порядок семей проверяются по утверждённому манифесту и оригинальному референсу. При расхождении ставится `REVIEW_REQUIRED`.

Не перезаписывать автоматически:

- `source/`;
- `assets/master-from-pdf/` и другие native/master-папки;
- утверждённые файлы в `assets/review/approved/`;
- существующие PDF прототипов;
- `content/manifests/reference-first-20-map.json` и `content/regions/regions.json` без фактической сверки.

Важно: ранние разделы этого handoff и документы v3/v5 содержат исторические правила «одна семья = один разворот», печатный excerpt и QR. Текущее правило имеет приоритет: ознакомительный разворот героя, затем отдельный разворот полного манифеста целиком; тематические карточки и смысловая нарезка запрещены. Устаревшие документы перечислены в `docs/graphify-project-review.md` и должны быть помечены historical/superseded до массовой верстки.
