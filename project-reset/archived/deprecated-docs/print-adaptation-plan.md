# План печатной адаптации

## Статус формата (предварительно)

**Горизонтальный книжный формат будет определён после получения технических требований типографии.** Рассматриваются пропорции около 260 × 200, 280 × 210 и 297 × 210 мм. Соотношение 16:9 (как в `source/horizontal-draft.pdf`, 960×540 pt) допустимо для цифрового прототипа, но **не утверждено как печатный формат**. Все макетные решения ниже привязаны к «горизонтальной полосе», а не к конкретной пропорции.

## Почему горизонтальный формат

Переработка уже начата в горизонтальной ориентации (`source/horizontal-draft.pdf`). Аргументы за горизонталь:

- **Материал альбомный по природе**: коллажи из 3–4 фото, письмо+фото, широкая карта России — в вертикальном A4 они давятся в столбик (что и видно в контрольном PDF).
- Разворот горизонтальной книги даёт **панораму**: слева титул героя, справа письмо; или письмо слева, фото справа — история читается одним взглядом.
- Фолиант-альбом на подарочных/презентационных мероприятиях смотрится статуснее; книга создавалась как книга-фолиант.
- Исходники — слайды PowerPoint 16:9: перенос в горизонтальную полосу близкой пропорции упрощает адаптацию композиций (но точная пропорция полосы — за типографией, композиции при необходимости пересобираются из сущностей).

## Типы разворотов (черновой набор)

| Разворот | Состав | Источник сущностей |
|---|---|---|
| Обложка/титул тома | название, том, издатель | Section, DocumentFragment |
| Служебный | указ, участники, выходные данные | DocumentFragment |
| Обращение | текст слева + портрет и автограф справа (паттерн уже в horizontal-draft) | DocumentFragment, Photo, Quote |
| Открытие блока героя | имя, регион, герб, карта + главное фото | Person, Photo |
| Письмо | скан крупно + (опц.) расшифровка колонкой | Letter |
| Фотогалерея героя | модульная сетка 2–4 изображений | Photo, Drawing |
| Смешанный | письмо + фото/рисунок | Letter, Photo, Drawing |
| Шмуцтитул раздела / цитатный | крупная цитата из письма | Quote, Section |

76 героев × 1–3 разворота + вводный блок ≈ 180–260 полос — сопоставимо с текущим объёмом.

## Что из веб-подачи НЕ переносится в печать

- Интерактив: фильтры, поиск, лайтбоксы, переключатель «скан/текст», анимации.
- Веб-компрессия: в печать идут только оригиналы из PPTX (300 dpi в конечном размере), не webp-вырезки из PDF.
- Бесконечная лента: в книге жёсткая пагинация и ритм разворотов.
- Свёрнутые тексты: в книге обращения публикуются полностью.

## Как общая база собирается в книгу

1. Редакция фиксирует порядок: `content/sections/*.json` → порядок героев и материалов внутри блока (поле `order`).
2. Каждому блоку героя назначается набор шаблонов разворотов (из таблицы выше) — «раскладка» хранится как данные (`design/layout-map.json`, будущий этап), а не правится руками в макете.
3. Генератор (будущий этап) собирает из сущностей пакеты для вёрстки: тексты + ссылки на оригинальные ассеты + тип разворота. Формат передачи в InDesign (IDML/скрипт) выбирается на этапе вёрстки — **не сейчас**.
4. Любая правка контента делается в базе и перекатывается в макет, а не наоборот — сайт и книга не расходятся.

## Блокеры печати до получения PPTX

- Изображения из контрольного PDF непригодны для типографии (пережаты экспортом PowerPoint).
- Точные тексты титулов героев с плейсхолдерами (7 стр. «НАШ ОТЕЦ ВЯЧЕСЛАВ…») восстановимы только из PPTX.
- Формат полосы, поля, вылеты — определяются после получения технических требований типографии (кандидаты: ~260×200, 280×210, 297×210 мм; 16:9 — только для цифрового прототипа).
