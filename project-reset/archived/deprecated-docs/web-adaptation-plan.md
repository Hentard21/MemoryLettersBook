# План веб-адаптации

## Почему не «выложить PDF на сайт»

- 20 МБ и 255 страниц: на мобильном соединении — десятки секунд до первого экрана; страница A4 на телефоне нечитаема без зума.
- 168 страниц — сканы без текста: нет поиска, нет индексации, нет доступности (скринридеры).
- Нет адресуемости: нельзя дать ссылку на историю конкретного героя — а это главный сценарий шеринга.
- Нет аналитики и нет пространства для будущих анимаций.
PDF остаётся на сайте только как **дополнительная опция** «Скачать книгу (PDF, ~20 МБ)».

## Структура сайта (маршруты из сущностей)

```
/                     — главная: миссия, цитаты, карта регионов, вход в истории
/heroes/              — каталог героев: фильтр по региону, поиск по имени
/heroes/<id>/         — страница героя (основная единица сайта)
/letters/<id>/        — страница письма (скан + расшифровка), шеринг
/about/               — о проекте, издатель, акция
/greetings/           — обращения и официальные документы (стр. 3–11 PDF)
/book/                — печатная книга: как получить + скачать PDF
```

Один герой = одна страница. Источник — `content/entities/heroes.pdf-stage.json` + связанные Letter/Photo/Drawing.

## Подача письма на сайте (ключевой паттерн)

1. **Скан письма** — почерк ребёнка и есть эмоциональное ядро; показывается всегда, с зумом.
2. **Расшифровка** — рядом (десктоп) или под сканом/переключателем «Текст письма» (мобильный). Появляется по мере ручной верификации (`transcript_status: verified`); до этого — только скан.
3. **Связанный герой** — имя, регион, ссылка на страницу героя.
4. **Метаданные** — автор письма, дата (дословно, как на письме), подписи.

## Десктоп

- Страница героя: шапка (имя, регион, метка на карте) → галерея фото/рисунков → письма.
- Двухколоночные композиции «скан + текст», лайтбокс для галерей.
- Карта России как навигация по регионам-участникам (стр. 3 PDF превращается в интерактив).

## Мобильные устройства

- Всё в одну колонку, порядок: имя героя → главное фото → письмо → остальная галерея.
- Изображения по ширине экрана, letter-скан с pinch-zoom.
- Никаких «разворотов»: печатная горизонтальная композиция не диктует мобильный UI — там из тех же сущностей собирается вертикальная лента. Попытка «уменьшить разворот до экрана» убивает читаемость и есть главная ошибка, которой избегаем.

## Форматы отдачи (позже, на этапе сборки)

- Тексты: structured JSON (сущности) + Markdown для длинных текстов.
- Изображения: AVIF + WebP с fallback JPEG; размерная сетка примерно 320/640/1280/2560 px, `srcset`; облегчённые превью (LQIP/blurhash) для каталога.
- Сканы писем: полноразмер webp/avif + превью; оригинал TIFF/PNG остаётся в архиве печати.
- Отдельный downloadable PDF — как опция, не как способ чтения.
- Целевой бюджет страницы героя: < 1 МБ первого экрана.

## Задел на будущее (анимации)

Структурированные сущности позволяют позже добавить: появление строк письма, параллакс рисунков, анимированную карту, переходы между героями — без переработки контента. Стилевая основа — триколорная гамма из `source/style-reference-presentation.pdf`.
