# Модель контентных сущностей (черновая, pdf-stage)

Единая база контента для книги и сайта. Каждая сущность хранится как JSON в `content/entities/` (позже — по файлу на сущность либо реестрами). Общие поля всех сущностей:

```jsonc
{
  "id": "…",                      // стабильный id, не меняется при замене исходников
  "source_quality": "pdf_reference | pptx_original | manual",
  "source_ref": { "pdf_page": 13, "pptx_slide": null },  // связь с исходниками
  "review_required": false,
  "review_reasons": [],
  "manual_notes": ""              // ручные пометки, НЕ перезаписываются скриптами
}
```

## Редакционные поля текстовых сущностей

Каждая сущность, несущая текст (Person, Letter, Quote, DocumentFragment, Section — заголовки), дополнительно содержит редакционный блок. Категории правок и правила — в `docs/AI_HANDOFF.md`, раздел «Editorial policy»; процесс — в `docs/editorial-workflow.md`.

```jsonc
{
  "source_text": "",            // дословный текст из исходника — НИКОГДА не изменяется
  "normalized_text": "",        // после SAFE_TECHNICAL_EDIT (пробелы, переносы, кавычки, тире, nbsp)
  "edited_text": null,          // утверждённая редакционная версия для сайта/печати
  "edit_status": "not_reviewed",
  "edit_category": null,        // SAFE_TECHNICAL_EDIT | APPROVAL_REQUIRED | FACT_LOCKED | UNCERTAIN_SOURCE
  "edit_reason": null,          // объяснение правки
  "edited_by": null,            // кто предложил (агент/человек)
  "approved_by": null,          // владелец проекта
  "approved_at": null,
  "source_reference": [],       // подтверждающие источники (обязательно для FACT_LOCKED)
  "editorial_notes": []         // свободные редакционные заметки
}
```

Допустимые значения `edit_status`:

```text
not_reviewed                  — текст не рассматривался редакцией
technical_edit_applied        — применена только техническая нормализация
proposal_created              — агент подготовил предложение правки (было/стало)
approval_required             — предложение ждёт решения владельца проекта
approved                      — правка утверждена, edited_text можно публиковать
rejected                      — правка отклонена, действует source/normalized текст
source_verification_required  — нужен подтверждающий источник (PPTX, семья, документы)
```

Правила: `source_text` неизменяем; `edited_text` заполняется только при `edit_status: approved`; в сайт и книгу попадает `edited_text` (если утверждён), иначе `normalized_text`; каждое изменение статуса отражается записью в `content/manifests/editorial-changelog.json`.

## Person (герой)

**Назначение:** центральная сущность — Герой, которому посвящён блок; вокруг неё группируются письма, фото, рисунки.

| Поле | Обяз. | Описание |
|---|---|---|
| `relation_phrase` | да | Дословно: «МОЙ ОТЕЦ», «МОЯ МАМА», «НАШ ОТЕЦ»… |
| `hero_first_name` | да | Имя героя дословно из титула |
| `hero_full_name` | нет | Полное ФИО — появится из PPTX/ручной сверки |
| `author_names[]` | да | Имена детей-авторов дословно |
| `region_raw`, `city_raw` | да | Регион и город дословно |
| `awards[]` | нет | Награды (на титулах есть изображения орденов — атрибуция только вручную/из PPTX) |
| `pages[]` | да | Диапазон страниц PDF блока героя |
| `links` | да | id связанных Letter/Photo/Drawing |

- **Связь с PDF:** титульная страница (`hero_title`) + следующие страницы-сканы до следующего титула.
- **Связь с PPTX:** слайды с теми же порядковыми номерами; полные тексты титулов.
- **Веб:** страница героя `/heroes/<id>` — заголовок, регион на карте, галерея, письма.
- **Печать:** открывающая полоса блока героя + развороты с материалами.

## Letter (письмо)

**Назначение:** рукописное (реже печатное) письмо ребёнка — смысловое ядро книги.

| Поле | Обяз. | Описание |
|---|---|---|
| `person_id` | да | Чей блок |
| `scan_asset` | да | Изображение скана |
| `author_name`, `date_raw` | нет | Дословно с письма, если читаемо (FACT_LOCKED) |
| `pdf_page` | да | Страница исходника |

Блок расшифровки (две версии — принципиально разные по назначению):

```jsonc
{
  "diplomatic_transcription": null,       // максимально точная передача оригинала:
                                          // авторская орфография, пунктуация, зачёркивания, разбивка строк
  "reader_friendly_transcription": null,  // читательская версия: исправленная пунктуация и очевидные
                                          // описки — ТОЛЬКО после утверждения владельцем проекта
  "transcription_status": "not_started",  // not_started / diplomatic_draft / diplomatic_verified /
                                          // reader_version_proposed / reader_version_approved
  "preserve_author_spelling": true,       // авторская орфография в diplomatic-версии сохраняется всегда
  "reader_version_approved": false        // true — только решением владельца проекта
}
```

- Массовый OCR по-прежнему запрещён; расшифровки — ручные/выборочные с верификацией.
- Исправление авторской орфографии и пунктуации — категория APPROVAL_REQUIRED (см. Editorial policy).
- **Веб:** скан + (позже) расшифровка рядом/переключателем: показывается `reader_friendly_transcription`, если утверждена, иначе `diplomatic_transcription`; метаданные; ссылка на героя.
- **Печать:** скан в максимальном качестве (нужен PPTX-оригинал); какая версия расшифровки идёт в книгу — решение редакции.

## Photo (фотография)

| Поле | Обяз. | Описание |
|---|---|---|
| `person_id` | да | Блок героя |
| `asset` | да | Файл изображения (сейчас — вырезка из PDF, потом — оригинал из PPTX) |
| `depicts` | нет | Кто изображён. **Заполняется только вручную — не угадывать!** |
| `caption_raw` | нет | Подпись, если есть в исходнике |
| `pdf_page`, `position_hint` | да | Страница и позиция на ней |

- **Веб:** галерея героя, webp/avif + lazy-load, превью.
- **Печать:** оригиналы 300 dpi из PPTX; из PDF — только как временные заглушки.

## Drawing (детский рисунок)

Поля как у Photo, плюс `author_name` (ребёнок-художник, если известно достоверно). Отличать рисунок от фото — при визуальной классификации; сомнение = `REVIEW_REQUIRED`.

- **Веб:** акцентный элемент (рисунки эмоционально сильны; кандидаты на анимации/параллакс).
- **Печать:** полосные/полуполосные иллюстрации.

## Quote (цитата)

**Назначение:** выделенные строки из писем и обращений для акцентной подачи (лендинг, шмуцтитулы, соцсети).

| Поле | Обяз. | Описание |
|---|---|---|
| `text_verbatim` | да | Дословный текст — категория FACT_LOCKED (цитаты не редактируются без источника и утверждения) |
| `source_entity` | да | id письма/обращения, откуда взята |
| `attribution_raw` | да | Подпись дословно |

- **Веб:** hero-блоки страниц, карточки шеринга.
- **Печать:** шмуцтитулы, врезки на разворотах.

## Section (раздел)

**Назначение:** крупный смысловой блок книги/сайта. Сейчас: `front-matter`, `heroes`; позже возможна группировка героев (по регионам/округам — решение редакции).

Поля: `title_working`, `pages[start,end]`, `children[]` (id сущностей по порядку), `order`.

- **Веб:** раздел = маршрут/оглавление сайта.
- **Печать:** раздел = тетрадь/блок с шмуцтитулом.

## PageUnit (страница исходника)

**Назначение:** технологическая привязка «как это лежало в PDF/PPTX»; мост между сущностями и исходником. Это НЕ финальная единица подачи.

Поля: `page`, `page_type` (архетип), `entity_refs[]`, `layout_hint`, `has_text_layer`, `image_count`, `needs_ocr`, `needs_review`. Хранится в `content/manifests/book-manifest.pdf-stage.json`.

- **Веб:** напрямую не используется — только как источник трассировки.
- **Печать:** отправная точка для маппинга «страница A4 → горизонтальный разворот».

## DocumentFragment (служебный/официальный текст)

**Назначение:** тексты вводного блока: указ, обращения, список участников, выходные данные, новостной блок.

Поля: `kind` (`official_document / greeting_letter / participants_list / imprint / news_block / dialogue_intro`), `text_raw` (дословно), `signatory_raw` (подписант дословно, со званиями), `pdf_page`.

- **Веб:** страницы «О проекте», «Обращения»; часть можно подать свёрнуто.
- **Печать:** вводный блок книги, порядок фиксирован редакцией.

## Принципы связей

```
Section 1—N Person 1—N (Letter | Photo | Drawing)
Quote N—1 (Letter | DocumentFragment)
PageUnit N—M (любая сущность)   // трассировка к исходнику
```

- id сущностей стабильны: замена PDF→PPTX меняет `source_ref` и `source_quality`, но не id.
- Любое поле, заполненное человеком, живёт в `manual_*`/`review_*` и не перезаписывается конвейером.
