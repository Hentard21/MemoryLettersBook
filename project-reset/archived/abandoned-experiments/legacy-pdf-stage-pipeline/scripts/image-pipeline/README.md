# Image-пайплайн (Riverflow / Recraft через OpenRouter)

**Статус: подготовлен, генерация НЕ запускалась.**

## Как устроено

| Файл | Что это |
|---|---|
| `../../.env.example` → `.env` | ключ `OPENROUTER_API_KEY` (настоящий ключ не коммитить: `.env` в `.gitignore`) |
| `../../config/image-models.json` | роли → модели: `portrait_editor` = Riverflow V2.5 Pro (вырезка портретов, лица не перерисовывать), `vector_graphics` = Recraft V4.1 Vector (карта, декор — НЕ гербы). Смена модели = правка этого файла |
| `../../content/manifests/image-jobs.json` | задания (сейчас 4 тестовых, статус `planned`) |
| `run_jobs.py` | раннер; по умолчанию **dry-run** |
| `logs/usage-log.jsonl` | журнал: модель, параметры, файлы, стоимость |

## Запуск

```
python scripts/image-pipeline/run_jobs.py            # dry-run: показать план, ничего не отправлять
python scripts/image-pipeline/run_jobs.py --execute  # реальный запуск (нужны: ключ в .env + status=approved_to_run)
```

Три предохранителя реального запуска: ключ в `.env`, флаг `--execute`, статус `approved_to_run` у job'а. Результаты идут в `assets/derived-ai/` (мастера не трогаются) и проходят приёмку перед использованием в макете.

## Правила

- Лица героев моделями **не перерисовываются** — только вырезка с фона.
- Гербы регионов **не генерируются** — только официальные файлы.
- Карта из модели — черновик; финальная сверяется с реальными геоданными.
- Каждый вызов пишется в журнал (модель + стоимость).
